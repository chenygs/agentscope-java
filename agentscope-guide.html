🧩 需要了解的核心概念

🤖 Agent 核心

是什么：智能体是 AI 应用的"大脑"，它接收消息、思考、做出回应。

接口：Agent / CallableAgent / StreamableAgent

基类：AgentBase — 你写代码时继承这个就行

现成的实现：

  • ReActAgent — 自带"思考→行动"循环的开箱即用 Agent ⭐
  • UserAgent — 代表人类用户的 Agent

🧠 Model 核心

是什么：对接各种大语言模型（LLM）的接口，比如 ChatGPT、通义千问、Claude 等。

接口：Model — 所有模型都实现这个接口

现成的实现：

  • OpenAIChatModel — OpenAI / 兼容接口
  • DashScopeChatModel — 阿里通义千问
  • AnthropicChatModel — Claude
  • GeminiChatModel — Google Gemini
  • OllamaChatModel — 本地部署模型

📦 Memory 核心

是什么：让智能体"记住"对话历史的东西。没有记忆，Agent 每次对话都是"失忆"的。

接口：Memory

现成的实现：

  • InMemoryMemory — 内存级记忆（重启就没了）⭐ 入门用
  • LongTermMemory — 长期记忆（跨会话）
  • StateBackedMemory — 基于状态存储的记忆

💻 代码案例：做一个最简单的聊天机器人

✅ 你的第一个智能体 这个例子只需要 3 个东西：ReActAgent（智能体）、DashScopeChatModel（模型）、InMemoryMemory（记忆）。 
// 1. 创建模型（选一个LLM）
Model model = DashScopeChatModel.builder()
    .apiKey(System.getenv("DASHSCOPE_API_KEY"))
    .modelName("qwen-plus")
    .build();

// 2. 创建记忆
Memory memory = new InMemoryMemory();

// 3. 创建智能体（开箱即用！）
ReActAgent agent = ReActAgent.builder()
    .name("我的第一个智能体")
    .sysPrompt("你是一个友好的助手。")
    .model(model)
    .memory(memory)
    .build();

// 4. 和它对话
Msg userMsg = Msg.builder()
    .role(MsgRole.USER)
    .content(TextBlock.builder().text("你好！").build())
    .build();

Msg response = agent.call(userMsg).block();
System.out.println(response.getTextContent());

🧩 新增的核心概念

🔧 Tool 核心

是什么：让 Agent 能"做事"的东西——查天气、算数学、发邮件、读文件……

注解：用 @Tool 和 @ToolParam 标记方法

关键类：Toolkit（工具包）、ToolRegistry（注册中心）

内置工具：

  • TodoTools — 任务规划（PlanNotebook）⭐
  • ReadFileTool / WriteFileTool — 文件读写
  • ShellCommandTool — 安全执行 shell 命令
  • SubAgentTool — 调用子智能体

🎯 Skill 扩展

是什么：技能的"仓库"。Tool 是单个功能，Skill 是一组相关能力+提示词的组合。

关键类：SkillRegistry、SkillBox、AgentSkill

集成方式：

  • SkillGitRepository — 从 Git 仓库获取技能
  • SkillMysqlRepository — 从 MySQL 获取技能
  • SkillPostgresqlRepository — 从 PostgreSQL 获取技能

Agent 通过 DynamicSkillMiddleware 动态加载技能

🔗 Hook 核心

是什么：在 Agent 执行的不同阶段"插入"自定义逻辑——像"钩子"一样。

接口：Hook — 只有一个方法 onEvent(T event)

生命周期事件（按执行顺序）：

  • PreReasoningEvent — 模型调用前（可修改消息）
  • PostReasoningEvent — 模型调用后（可修改响应）
  • PreActingEvent — 工具执行前
  • PostActingEvent — 工具执行后
  • ReasoningChunkEvent — 流式推理片段
  • ErrorEvent — 异常发生时

优先级：0（最高）→ 1000（最低）

📚 RAG 扩展

是什么：检索增强生成——让 Agent 能从知识库中查找信息后再回答。

关键类：Knowledge、KnowledgeRetrievalTools

现成的集成：

  • RagDify — Dify 知识库
  • RagBailian — 阿里云百炼
  • RagHaystack — Haystack
  • RagRagFlow — RagFlow
  • RagSimple — 简单本地实现

模式：RAGMode.AUTO（自动检索）、RAGMode.MANUAL（手动）

📋 Pipeline 核心

是什么：编排多个 Agent 按顺序或并行执行。在复杂 Agent 中，可以用来给单个 Agent 增加处理步骤。

关键类：SequentialPipeline（顺序执行）、FanoutPipeline（并行执行）

使用场景：

  • 输入先经过"预处理Agent"→ 主 Agent → "后处理Agent"
  • 多个 Agent 并行分析不同维度 → 汇总结果

📝 Middleware 核心

是什么：Agent 执行流程的"管道"。所有推理（Reasoning）和行动（Acting）都通过中间件链串联。

关键类：MiddlewareChain、MiddlewareBase

中间件节点：

  • ReasoningInput — 推理阶段
  • ActingInput — 行动（工具调用）阶段
  • ModelCallInput — 模型调用
  • AgentInput — Agent 输入处理
  • TaskReminderMiddleware — 任务提醒

💡 大多数情况下你不用直接操作中间件，框架帮你管理好了。

💻 代码案例：带工具和 Hook 的智能体

✅ 复杂智能体示例 这个 Agent 能做两件事：1）查天气（通过 Tool）；2）在每次思考时打印日志（通过 Hook）。它还有一个"任务规划"工具帮它分解复杂任务。 
// ===== 第一步：定义工具 =====
public class WeatherTools {
    @Tool(description = "获取指定城市的天气")
    public String getWeather(
            @ToolParam(name = "city", description = "城市名")
            String city) {
        // 这里可以调真实 API，这里模拟返回
        return String.format("%s: 晴天, 25°C", city);
    }
}

// ===== 第二步：创建 Hook（日志钩子） =====
Hook logHook = new Hook() {
    @Override
    public <T extends HookEvent> Mono<T> onEvent(T event) {
        if (event instanceof PreReasoningEvent) {
            log.info("🤔 Agent 开始思考...");
        } else if (event instanceof PreActingEvent e) {
            log.info("🛠️ Agent 要调用工具: {}", e.getToolUse().getName());
        } else if (event instanceof PostActingEvent e) {
            log.info("✅ 工具执行完成: {}", e.getToolUse().getName());
        }
        return Mono.just(event);
    }
    public int priority() { return 500; }
};

// ===== 第三步：组装智能体 =====
Toolkit toolkit = new Toolkit();
toolkit.registerTool(new WeatherTools());   // 注册自定义工具
toolkit.registerTool(new TodoTools());        // 注册内置任务规划工具

ReActAgent agent = ReActAgent.builder()
    .name("全能助手")
    .sysPrompt("你是一个有用的助手。使用工具来帮助用户。")
    .model(model)
    .memory(new InMemoryMemory())
    .toolkit(toolkit)        // ← 配工具
    .hook(logHook)           // ← 配钩子
    .maxIters(10)            // 最大推理-行动循环次数
    .build();
⚠️ ReAct 循环是什么意思？ ReAct = Reason（推理）+ Act（行动）。Agent 会不断循环：思考需要做什么 → 调用工具 → 得到结果 → 再思考 → 再调用…… 直到完成任务。maxIters 限制了最大循环次数，防止无限循环。

💻 代码案例：多智能体内容创作团队

✅ 案例：一个内容创作团队 三个 Agent 协作：研究员（搜索资料）→ 写作者（撰写文章）→ 审核者（审核质量）。 
// 1. 创建三个 Agent
ReActAgent researchAgent = ReActAgent.builder()
    .name("研究员")
    .sysPrompt("你是一个研究员。搜索并总结信息。")
    .model(model)
    .build();

ReActAgent writeAgent = ReActAgent.builder()
    .name("写作者")
    .sysPrompt("你是一个技术写手。根据研究结果撰写文章。")
    .model(model)
    .build();

ReActAgent reviewAgent = ReActAgent.builder()
    .name("审核者")
    .sysPrompt("你是一个编辑。检查文章质量，给出修改建议。")
    .model(model)
    .build();

// 2. 顺序执行：研究员 → 写作者 → 审核者
Msg result = SequentialPipeline.builder()
    .addAgent(researchAgent)
    .addAgent(writeAgent)
    .addAgent(reviewAgent)
    .build()
    .execute(Msg.builder()
        .role(MsgRole.USER)
        .content(TextBlock.builder()
            .text("写一篇关于 AI Agent 的科普文章")
            .build())
        .build())
    .block();

System.out.println(result.getTextContent());
💡 什么时候用哪种模式？
场景推荐模式原因
流水线作业（调研→写→审）SequentialPipeline每一步依赖上一步结果
多维度分析（同时分析代码、安全、性能）FanoutPipeline各维度独立，可并行
主 Agent 动态分配任务SubAgent任务数量和类型不确定
跨服务调用A2AAgent 在不同进程中

⚙️ MiddlewareChain（中间件链）— 智能体的执行管道

是什么：Agent 的执行流程由中间件链驱动。每次"推理→行动"循环都通过这个链完成。

关键类：MiddlewareChain

中间件节点：

  • ReasoningInput — 处理推理输入
  • ModelCallInput — 执行模型调用
  • ActingInput — 处理工具调用
  • AgentInput — Agent 级别的输入处理
  • TaskReminderMiddleware — 任务提醒

执行流程详解：

Agent.call()
  └─ PreCallEvent (Hook)
  └─ MiddlewareChain.start()
     └─ AgentInput.process()
     └─ 循环开始
        ├─ PreReasoningEvent (Hook)
        ├─ ModelCallInput → Model.generate()
        ├─ PostReasoningEvent (Hook)
        ├─ 需要调用工具？
        │  ├─ PreActingEvent (Hook)
        │  ├─ ActingInput → ToolExecutor
        │  └─ PostActingEvent (Hook)
        └─ 回到循环开始
  └─ PostCallEvent (Hook)
🎯 Skill（技能）— 智能体的知识包

是什么：Skill 是一组"提示词 + 工具"的组合。一个技能包可能包含：

  • 系统提示词（教 Agent 如何做某件事）
  • 相关工具（做这件事需要的工具）
  • 示例（few-shot 示例）

关键类：

  • AgentSkill — 技能的定义
  • SkillRegistry — 技能注册中心
  • SkillBox — 技能容器
  • SkillHook — 技能相关的 Hook
  • DynamicSkillMiddleware — 动态加载技能

仓库实现（技能存在哪）：

  • SkillGitRepository — Git 仓库 ⭐
  • SkillMysqlRepository — MySQL

// 通过 MCP 协议连接文件系统服务器
McpClientWrapper mcpClient = McpClientBuilder.stdio()
    .command("npx")
    .args("-y", "@modelcontextprotocol/server-filesystem", "/path")
    .build();

Toolkit toolkit = new Toolkit();
toolkit.registration()
    .mcpClient(mcpClient)
    .enableTools(List.of("read_file", "write_file"))
    .apply();

// Agent 现在可以用 read_file 和 write_file 工具了！
